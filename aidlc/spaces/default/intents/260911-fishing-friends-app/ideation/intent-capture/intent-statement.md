# Intent Statement — 友達と使う釣りアプリ

## Sources

- [desc] Initial description: "友達と釣りに行きます。釣りアプリを作りたいです。"
- [scope] Workflow-selected scope: `fishing-app-greenfield`.
- 確認済み回答: `intent-capture-questions.md` の Q1〜Q11（本文中では `[Q<n>]` で参照）

## Problem Statement（解決したいこと）

- 友達と釣りに行く際に使う、自分たちのための釣りアプリを作る。[desc]
- 特定の「困りごと」を解決するためではなく、釣りをより楽しむための道具として作る。現状の不便さは特に挙がっていない。[Q3]
- アプリの中心となる価値は次の3つ。[Q1]
  - 釣果の記録・共有（釣った魚の写真・サイズ・場所・日時を残して見せ合う）[Q1]
  - 釣り場（ポイント）情報の共有（場所・行き方・釣れた条件のメモ）[Q1]
  - 釣行中のリアルタイム連絡（今どこにいる・何が釣れた、を即時に共有）[Q1]
- 3つのうち、次の釣行までに最優先で動かすのは「釣果の記録・共有」。残り2つは間に合わなければ釣行後でもよい。[Q10]

## Target Customer（誰のためか）

- 一次利用者: 自分（作る本人）と、一緒に釣りに行く友達。[desc][Q2]
- 二次利用者: 友達の知り合いなど、ゆるく広がるグループの参加者。不特定多数への公開は想定していない。[Q2]
- 得られる価値: 釣行ごとの釣果とポイント情報がグループ内に残り、見せ合える。釣行中は互いの状況を即時に知れる。[Q1][Q4]

## Success Metrics（成功の姿）

- 次の釣行（1〜2週間以内）の当日に、自分の端末上で動くアプリに釣果の記録が登録され、同行した友達にその場で見せられる状態になっている。判定: できた／できなかった。[Q4][Q9][Q11]
- 次の釣行以降、釣行のたびに記録がアプリに積み上がっていく。判定: 釣行ごとに記録が残っているか。[Q4]
- 上記の判定に、友達各自の端末からの利用は含めない（それは次の釣行より後の段階）。[Q9]

## Initiative Trigger（なぜ今か）

- 近いうちに（1〜2週間以内に）友達との釣行が予定されており、それまでに使える状態にしたい。[Q5][Q11]
- 既存アプリへの不満や外部からの依頼ではなく、自分発の取り組み。[Q5]

## Initial Scope Signal（範囲の手がかり）

### workflow-selected（この作業の進め方として選ばれた範囲）

- 進め方: `fishing-app-greenfield`（workflow-selected）。「何を作るかを固める → 設計 → 実装 → 自動テスト → CI」までを扱い、公開（デプロイ）・運用は含まない。[scope]

### user-confirmed（本人が確認した作るものの範囲）

- 上記の進め方の範囲で合っている。公開は後で別の作業として行う。[Q8]
- 次の釣行では、自分の端末でアプリを動かして友達に見せる。友達各自の端末で使えるようにするのはその後。[Q9]
- 次の釣行までに動いていてほしいのは「釣果の記録・共有」。ポイント情報の共有とリアルタイム連絡は、間に合わなければ釣行後でもよい。[Q10]
- 何を作るか・何を優先するかは自分ひとりで決める。開発中の友達への共有・報告は不要。[Q6][Q7]

## Assumptions & Open Questions

- 「釣行中のリアルタイム連絡」の具体的な中身（位置情報の共有なのか、釣果投稿の即時通知なのか、チャットなのか）は未確定。[assumption]
- 「友達の知り合い」がどのようにグループへ参加するか（招待の仕組みの有無）は未確定。[assumption]
- 「記録が積み上がっている」と判定する件数の目安（釣行ごとに1件以上、など）は未確定。[assumption]
